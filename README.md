## 〇、先说大实话：已知弊端与三条路对比

在决定要不要动手搓卡片之前，先把我们实测踩出来的 **4 条真实局限** 摆在台面上：

| 序号 | 已知弊端与局限 | 真实体感说明 |
|---|---|---|
| **1** | **操作比微信原生面板多两步** | 发图需要先点开顶部「应用」→ 打开斗图盒卡片 → 点图发送（或复制粘贴），不如输入框旁原生抽屉顺手 |
| **2** | **人类方在卡片里只能单张添加** | 人类自己在卡片右上角「＋添新图」只能填名字和 URL 一条条加；想一次性塞几十张，需要把图片 URL 列表发给小机，让小机写进源码或调用 `addSticker` 工具批量收录 |
| **3** | **没有 VPS 就得依赖公共图床** | 公共图床偶尔会慢、会限流或 404 裂图；没服务器完全可以用免费图床顶上，但建议挑国内节点的图床并把 GIF 压到 100KB 以内 |
| **4** | **有一条零开发的替代正路** | 如果你不爱折腾卡片，**直接在手机相册里建一个置顶的「表情包相簿」**，或者用 **手机键盘「文本替换」**，发图也很稳 |

### 📊 人类发表情包的三条路线怎么选？

| 对比维度 | 路线 A：手机相册建专门相簿 | 路线 B：图床直链 + 键盘文本替换 | 路线 C：房间表情包抽屉卡片（本文方案） |
|---|---|---|---|
| **折腾成本** | ⭐ 零成本 | ⭐⭐ 5 分钟 | ⭐⭐⭐ 15～30 分钟 |
| **发图方式** | 点输入框旁附件 → 相册选图发送 | 打缩写词（如 `bqb贴`）自动吐出 `![贴贴](https://...)` | 点开卡片（支持**缩小悬浮窗**）→ 看缩略图点选即发 |
| **最大优势** | 永远不会裂图，不用管图床 | 不用离开输入框，打字顺手秒出 | **看得见全套缩略图**，支持分类筛选，缩成小窗边聊边看 |
| **最适合谁** | 嫌麻烦、偶尔发图的伙伴 | 最常用表情包固定在 15 张以内的伙伴 | 表情包大户（50～100+ 张）、喜欢看着图翻牌子的伙伴 |

## 一、实际运作架构与数据流向

这套方案能够跑通的底层前提只有一个：**Aru 的人类侧与 AI 侧聊天气泡，均原生支持渲染 `![表情名](https://图片直链)` 格式的公网图片。**

```text
【准备阶段：图片变成秒开直链】
 手机相册表情包 (.gif / .png / .jpg)
       │
       ├──► 路线 1（零服务器）：上传至稳定图床 ──► 获得 https://图床域名/xxx.gif
       │
       └──► 路线 2（自建进阶）：放进自家 VPS /var/www/stickers/ ──► https://自家域名/stickers/d1.gif

【使用阶段：双端斗图闭环】
 ┌─────────────────────────────────────────────────────────────────┐
 │ 人类侧：打开「🐰 斗图盒」卡片（可点右上角缩小成悬浮小窗，边聊边看） │
 │   ├─ 点击任意缩略图 ──► 自动发送 / 复制 ![贴贴](https://.../d5.gif) │
 │   ├─ 右上角「✕」    ──► 随时删掉不喜欢的表情包（支持一键恢复默认）   │
 │   └─ 批量加新图     ──► 把新图 URL 列表丢给小机 ──► 小机批量焊入卡片  │
 └─────────────────────────────────────────────────────────────────┘
                                 │
                                 ▼
                   Aru 聊天气泡直接渲染出动态表情包
                                 ▲
                                 │
 ┌─────────────────────────────────────────────────────────────────┐
 │ AI 侧：绑定「表情包世界书」（role = assistant + 正则关键词触发）     │
 │   └─ 聊到对应情绪词 ──► 自动在回复中甩出 ![生气](https://.../d2.gif) │
 └─────────────────────────────────────────────────────────────────┘
```

## 二、核心亮点功能

| 功能模块 | 实际体验细节 |
|---|---|
| **1. 网页卡片「缩小」悬浮窗** | Aru 打开房间卡片后支持**缩小窗口**功能——可以把斗图盒缩在屏幕一角，一边看着聊天框和小机斗嘴，一边顺手戳缩略图，不用来回切全屏 |
| **2. 多分类药丸栏秒切** | 表情包按 `全部 / 日常动图 / 撒娇 / 抽象` 等分成不同抽屉，100 张图找起来也不眼花 |

## 三、保姆级部署步骤（直接抄作业）

### 第一步：准备你的表情包 URL 列表

不管你用免费图床还是自家 VPS，先把你想用的表情包上传好，整理成下面这种「名字 + 直链」的格式：

```markdown
![贴贴](https://你的图床或域名/stickers/d5.gif)
![撒娇](https://你的图床或域名/stickers/d6.gif)
```

> 💡 **体积小贴士**：尽量选单张 **10KB～150KB** 的 `.gif` 动图或静态图，发进气泡几乎是毫秒级秒出；超过 3MB 的大图在移动网络下会有明显的加载转圈。

### 第二步：使用本仓库模板或让小机一键搓出卡片

可以直接把本仓库的 `sticker-box-card.html` 喂给小机修改默认列表，或者复制下面这段话发给你的协作者小机，让他调用 `createCard` 创建：

```text
请帮我用 createCard 创建一个房间卡片，名字叫「🐰 专属斗图盒」。要求如下：
1. 界面包含顶部分类药丸标签栏（如：全部、日常、撒娇、抽象）、右上角「＋添新图」折叠面板和「恢复默认」按钮。
2. 主体为 3 列网格缩略图，每张图右上角带一个小「✕」删除按钮，点击可从当前列表中移除。
3. 点击任意表情包卡片时：复制对应的 Markdown 语法 `![名称](URL)` 到剪贴板，并在底部弹出轻提示「已复制，去输入框粘贴发送～」。
4. 状态持久化保存在 PolarisRoom state 中，删图或添图后刷新不丢失。
5. 注册协作者工具 action `addSticker(name, url, cat)` 和 `listStickers()`，方便以后我直接发 URL 让你帮我往盒子里加图。
以下是我要内置进去的第一批默认表情包列表：
【在这里粘贴你的表情包名称和 URL】
```

### 第三步：如果想在聊天正文里先「零卡片试试水」（`aru-app` 写法）

如果不想先建独立卡片，小机也可以直接在回复正文里写原生 `<aru-app>` 组件，点按钮就能直接把表情包作为人类回复发出去：

```xml
<aru-app state='{tab:"cute"}'>
  <aru-card label='🐰 秒发斗图小抽屉' style='inset'>
    <aru-row>
      <aru-button style='primary' set='tab="cute"'>💞 撒娇</aru-button>
      <aru-button style='secondary' set='tab="angry"'>💢 小脾气</aru-button>
    </aru-row>
    <aru-divider/>
    <aru-show if='tab=="cute"'>
      <aru-grid cols='2'>
        <aru-card style='plain'>
          <aru-image src='https://你的域名/stickers/d5.gif' ratio='1:1' alt='贴贴'/>
          <aru-button style='primary' repeat='true' send='![贴贴](https://你的域名/stickers/d5.gif)'>💞 发「贴贴」</aru-button>
        </aru-card>
      </aru-grid>
    </aru-show>
  </aru-card>
</aru-app>
```

### 第四步：给小机配好「世界书表情包库」（让 AI 也会主动甩图）

| 世界书配置项 | 推荐填写值 | 为什么要这样配 |
|---|---|---|
| **注入位置 (`position`)** | `before_collaborator_prompt` | 确保小机在组织语言前先看到当前触发的表情包 |
| **条目角色 (`role`)** | `assistant` | 让小机把图片 Markdown 当成自己嘴里可以直接吐出来的表达 |
| **匹配方式** | `regex`（正则匹配） + 触发概率 `100%` | 一条正则如 `(生气\|气\|炸毛\|哼\|不高兴)` 就能覆盖十几种相近语境 |
| **条目内容 (`content`)** | `![生气](https://你的域名/stickers/d2.gif)` | 纯净一行 Markdown，小机想发时直接原样输出 |

## 四、进阶选配：把表情包搬进自家 VPS（彻底告别裂图）

> ⚠️ **没有 VPS 的伙伴请直接跳过本章！** 用稳定的图床完全够用。只有当你受够了公共图床抽风、404 裂图，并且手里有一台绑好 HTTPS 域名的服务器时，再看这一节。

### 4.1 批量把外链图片拉取到服务器本地

```bash
sudo mkdir -p /var/www/stickers
cd /var/www/stickers

dl() {
  curl -sL --max-time 25 -o "$1" "$2" \
    && echo "OK $1 $(du -h "$1" | cut -f1)" \
    || echo "FAIL $1"
}

dl d5.gif 'https://原图床地址/xxx.gif'
```

> 🔍 **防坑细节**：跑完一定要看一眼文件大小！如果某张动图显示只有 **`4.0K`**，说明原图床已经 `404` 了，`curl` 下回来的是一个 404 报错网页而不是真图片。

### 4.2 配置 Nginx 静态直出与 7 天强缓存

在你的域名**真正生效的那个 `443 ssl` server 块**里加上 `/stickers/` 路由：

```nginx
location /stickers/ {
    alias /var/www/stickers/;
    expires 7d;
    add_header Cache-Control "public";
    add_header Access-Control-Allow-Origin "*";
}
```

改完后验配置并全量体检：

```bash
sudo nginx -t && sudo systemctl reload nginx
for f in /var/www/stickers/*; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "https://你的域名/stickers/$(basename "$f")")
  echo "$(basename "$f"): $code"
done
```

## 五、高频踩坑与排错总表

| 踩坑现象 | 真正原因 | 一步到位解法 |
|---|---|---|
| **1. 发的表情包老是裂开（显示灰块）** | 公共图床链接失效（404）、防盗链拦截，或者世界书里还留着旧图床地址没换干净 | 迁移至稳定图床/自建 VPS，并让小机用 `configureWorldBook` 把世界书全量条目一次性换血成本地新链接 |
| **2. VPS 上文件明明下好了，访问 `/stickers/xx.gif` 却一直 `301` 跳转** | Nginx 里有多个监听 `443` 的 `server` 块写着同一个 `server_name`，你改的块没排在第一个生效，请求落进了别的 `location /` 兜底重定向 | 用 `grep -rn "server_name 你的域名" /etc/nginx/` 找出排在最前面、真正接管 443 流量的那个配置文件，把 `location /stickers/` 加进那个块里 |
| **3. 小机给卡片换了新链接，我打开卡片看到的还是旧图** | 房间卡片为了保留你的删图记录，把旧列表存在了本地 `state / localStorage` 缓存里 | 打开斗图盒卡片，点一下右上角的 **「恢复默认」** 按钮，即可强制刷出最新全量图库 |
| **4. 直接把图片当聊天附件发给小机，小机没法直接塞进盒子** | 聊天窗口上传的附件本身没有长期公开的 `https://` 外链，聊天气泡没法直接用内部引用渲染 | 先把图传到图床（或发给小机让他帮你传到 VPS `/stickers/` 目录），拿到 `https://` 直链后再入库 |

## 七、真实使用总结 & 结语

折腾这一整圈下来，这套「房间斗图盒卡片 + 世界书联动」的优缺点其实非常分明：

- **它的真实短板**：人类方往卡片里加图如果要批量塞，还是得把图片 URL 发给小机帮忙收录，自己在卡片面板上只能单张手动加；而且每次斗图要比原生输入框多点两下。
- **它的独家爽点**：Aru 打开网页卡片自带**「缩小」悬浮窗功能**——可以把斗图盒缩成小窗挂在聊天界面一角，一边看字聊天一边顺手戳缩略图，这是普通相册发图给不了的陪伴感。
- **关于图床的实在建议**：手里没有 VPS 服务器的伙伴，老老实实用稳定图床 + 压小动图体积就完全够用；甚至如果不想用卡片，直接在手机相册里建一个「置顶表情包相簿」或者用键盘「文本替换」，也是零成本的正路。

工具只要顺着自己的习惯长就好。最后还是许愿哪天 Aru 开发老师能给人类输入框旁边加一个原生的「常用表情包小抽屉」——在那天到来之前，希望这份实录能帮大家实现双向斗图自由！✨
